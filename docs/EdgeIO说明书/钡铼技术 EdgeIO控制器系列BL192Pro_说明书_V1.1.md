# 产品简介

## 概述

工业物联网边缘I/O控制器是钡铼技术推出的工业级EdgeIO控制器，作为一款支持MQTT、Modbus TCP、OPC UA三大主流协议，集数据采集、跨协议转换、逻辑控制、远程运维于一体的多功能边缘计算设备，BL192Pro支持 1-3 个 IO 扩展槽位，用户可根据现场需求自由组合数字量、模拟量、温度、串口等多种 I/O 模块，灵活适配各类工业自动化场景。例如，BL192Pro可以搭配3块Y11（8DI）组成24DI独立式IO模块，或者混搭不同类型的IO板，如Y11（8DI）、Y31（4AI）、Y52（2PT）即可组合成8DI+4AI+2PT独立式IO组成一个既有数字输入（DI）、模拟输入（AI）、又有热电阻输入（PT）的IO模块。它无需额外网关就可以同时对接物联网平台、PLC控制系统和企业管理系统，实现从现场设备到云端/上层平台的无缝数据互通；同时可独立完成寄存器运算、条件判断等本地逻辑控制任务，有效降低系统部署成本和复杂度。

一台BL192Pro设备即可完成：

采集现场传感器、仪表信号，并执行本地逻辑控制。

作为 Modbus RTU 从站，接入现有 HMI、触摸屏，保留原有操作习惯。

通过 MQTT 将数据上传至公有云或私有云平台，实现远程监控。

通过 OPC UA 将数据开放给 MES、ERP、SCADA 等上层管理系统。

一台 BL192Pro，替代“PLC + I/O 模块 + 协议转换网关 + 云网关”的繁琐组合，实现从现场到云端的全链路数据贯通。

![image](钡铼技术 EdgeIO控制器系列BL192Pro_说明书_V1.1-images/image3.jpeg)

BL192Pro工业物联网边缘I/O控制器采用电气隔离技术，通过EMC/EMI测试及-45~80℃高低温验证，内置独立硬件看门狗，确保在严苛环境下长期稳定运行。广泛应用于分布式物联网监测、智慧农业、智慧水务、储能系统、远程设备管理等领域，为多协议并存的复杂工业场景提供可靠、易部署、易维护的边缘层解决方案。


## 典型应用

典型应用案例：老旧生产线智能化改造

背景

某汽配工厂有一条 10 年前建成的冲压生产线，原有控制系统由 PLC 加普通 I/O 组成，但 PLC 品牌已停产，故障频发。现场有一台 HMI（触摸屏）通过 Modbus RTU 与 PLC 通信，用于显示设备状态和手动启停。

工厂希望实现以下目标：

保留原有 HMI 的操作界面，避免重新培训工人。

采集生产线能耗数据、冲压次数（OEE），上传至工厂云平台。

实现远程故障诊断和参数调整，减少停机时间。

改造方案

采用 BL192Pro 替换原有 PLC 和 I/O 模块，完全保留原有 HMI。

I/O 采集：BL192Pro 通过 DI 采集冲床运行/故障信号，通过 AI 采集电流/压力信号，通过高速计数通道采集冲压次数。

本地逻辑控制：内置 Web 配置实现 急停信号触发 → DO 切断运行、冲压次数每日自动清零等逻辑。

Modbus RTU 从站：BL192Pro 模拟原 PLC 的 Modbus 地址映射，原有 HMI 无需任何修改即可读写设备状态（读取 DI 状态、写入 DO 控制命令）。

MQTT 上云：将冲压次数、电流峰值、运行时长等数据通过 MQTT 上传至工厂私有云平台，生产看板实时显示 OEE。

OPC UA 开放：将关键数据以 OPC UA 接口提供给 MES 系统，用于质量追溯和分析。

远程运维：工程师通过 BLRAT 远程工具修改计数清零时间、报警阈值，排查故障，无需到车间现场。

收益


| 项目 | 改造前 | 改造后 |
| --- | --- | --- |
| 硬件设备 | PLC + 普通 I/O（停产） | 一台 BL192Pro |
| HMI 改造 | 需重新编程，周期长 | 零改动，直接兼容 |
| 数据上云 | 不支持 | MQTT 直连云平台，实时监控 |
| MES 对接 | 无接口 | OPC UA 标准接口，即连即用 |
| 现场维护频率 | 每周至少 1 次 | 远程诊断，现场次数减少 80% |
| 年停机时间 | 约 40 小时 | 降低至 10 小时以内 |

结论：BL192Pro 以一台设备同时实现了 IO 采集、HMI 接入、云端上报和 MES 对接，保留了客户原有 HMI 资产，每年节省运维成本超 5 万元。

## 功能特点

灵活的组合选项：用户可以根据需求自由组合1-3块Y系列IO板，支持多种配置，如24DI、16DI+8DO、8DI+4AI+2PT等，满足不同工业自动化场景的需求。

多样化的类型：支持数字量输入（DI）、数字量输出（DO）、模拟量输入（AI）、模拟量输出（AO）、热电阻输入（PT）和热电偶输入（TC）、数字量输入输出混合IO（DIDO）和脉冲输出/脉冲计数混合IO，适用于各种信号采集和控制任务。

工业级设计：通过EMC/EMI测试和-45~80℃宽温测试，能够在恶劣的环境条件下稳定运行，确保系统的可靠性。

多协议：支持MQTT、Modbus、OPC UA三大主流协议，支持阿里云、华为云、AWS IoT、Thingsboard平台连接。

边缘计算功能：内置逻辑控制和边缘计算，能够在本地执行一些简单的任务，减少对中央控制器的依赖。

交换机功能：配置2个RJ45接口，内置交换机功能，能够轻松建立线路拓扑结构，减少对额外交换机或集线器的需求，简化网络配置。

数据采集：自带1路隔离的RS485，支持Modbus RTU主站/从站双模式，可直连接智能仪表、传感器等设备，也可作为从站响应上位机指令；也可以通过网口采集Modbus TCP设备数据。。

远程维护：集成BLRAT（Beilai Remote Access Tool），支持远程固件升级及参数配置，无需到现场调试与修改。

BL192Pro是BL192 MQTT协议边缘I/O控制器的增强版。

## OPC UA数据点Node Id

BL192Pro支持OPC UA Server功能，以服务器形式对外提供数据。

OPC UA的Node Id 默认是NS=1；S=I/O数据点的Modbus映射地址(如首个DO模块第一路DO：NS=1；S=1000)，具体Modbus映射地址参考4.3Modbus 寄存器映射。


## MQTT标识符

MQTT标识符是REG+Modbus映射地址(如首个DO模块第一路DO：REG1000)，具体Modbus映射地址参考4.3Modbus 寄存器映射。


## EdgeIO控制器连接

BL192Pro 有2个以太网接口，内部集成交换机功能，工作在存储转发操作模式，每个端口支持10/100 Mbit的传输速度以及全双工和半双工传输模式。

该EdgeIO控制器只能通过ETH 0接口连接到基于以太网的现场总线中，ETH1用于连接其他需要接入以太网的节点。

内部集成的交换机支持旁路模式，当EdgeIO控制器系统故障时可以自动启动旁路模式，自动维持 ETH 0 和 ETH 1的链接。

这些以太网接口的接线符合 100BaseTX 的规范，该规范规定使用 5 类双绞线电缆作为连接电缆。可以使用最大长为 100 m的电缆类型 S/UTP（屏蔽非屏蔽双绞线）和 STP（屏蔽双绞线）。

## 登录网页配置

BL192Pro 内置web服务器是一个基于浏览器的配置实用程序。当节点连接到您网络时，您可以在 Web 浏览器中输入服务器的 IP 地址以访问 Web 控制台。


### 连接与IP配置

想要顺利的访问BL192Pro节点，必须要将它正确的安装并且和计算机建立连接。除此之外还要给它们配置正确的IP地址，使他们保持在同一个网段内。


#### 连接计算机和EdgeIO控制器

将现场总线节点安装到DIN35导轨上。按照“产品安装”章节中的安装说明进行操作。

将 24 V 电源连接到电源端子。

计算机和总线节点可以通过2种方式建立连接，一种是两者通过以太网接口接入本地局域网的交换机设备；另一种是两者点对点直接相连。详细步骤请按照“EdgeIO控制器连接”章节中的说明进行操作。

将电源开机，开始供电。

I/O模块上电工作后被初始化，同时根据现场总线节点的 I/O 模块配置并创建过程映像。


#### 配置计算机IP地址

模拟量输入模块的电信号数值（一般是传感器）和实际工程数值存在线性关系，它们的公式如下（以4-20mA为例）：

实际工程数值 =（电流值 - 4）*（（最大值 – 最小值）/（20 - 4））+最小值

以 4-20mA 类型的水位传感器测量水塔深度为例：

已知水位传感器量程是0-100m，电流数据5.6mA，计算水塔深度：

代入公式：

(5.6 - 4) * ((100 - 0) / (20 - 4)) + 0 = 10

水塔深度是10m。

### Modbus TCP通信示例

#### 概述

Modbus 是一种独立于制造商的开放式现场总线标准协议，适用于制造和过程自动化中的各种应用。

MODBUS 是一种应用层消息传递协议，位于 OSI 模型的第 7 层，可以在不同类型的总线或网络上连接的设备之间进行客户端/服务器通信。

几种常用的网络如下：

TCP/IP over Ethernet。

多种媒体异步串行传输（有线：EIA/TIA-232-E、EIA-422、EIA/TIA-485-A；光纤、无线电等）。

MODBUS PLUS，高速令牌。

MODBUS 是一种请求/应答协议，提供由功能代码指定的服务。

MODBUS 协议允许在所有类型的网络架构内轻松通信。

![image](钡铼技术 EdgeIO控制器系列BL192Pro_说明书_V1.1-images/image131.png)

Modbus 网络架构

MODBUS 协议定义了一个独立于底层通信层的简单协议数据单元 (PDU)。 MODBUS 协议在特定总线或网络上的映射可以在应用数据单元（ADU）上引入一些附加字段。

![image](钡铼技术 EdgeIO控制器系列BL192Pro_说明书_V1.1-images/image132.png)

Modbus 数据帧

更多关于 Modbus 开放协议规范的细节可以在网站www.modbus.org查看。


#### Modbus TCP

Modbus TCP协议是Modbus协议的一种变体，该协议经过优化，可通过TCP/IP连接进行通信。该协议设计用于现场级的数据交换（即用于过程映像中的 I/O 数据交换）。在服务端，所有数据包都通过端口号为 502 的 TCP 连接发送。

一般 Modbus TCP 报文如下：

Modbus TCP 报文


| 字节 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 - n |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 定义 | 事务标识符 | 协议标识符 (始终为00) | 字段长度 | 从机地址 | Modbus 功能码 | 数据 |  |  |  |


#### Modbus数据编码

MODBUS对地址和数据项使用“大端”表示。这意味着当传输大于单个字节的数字量时，首先发送最高有效字节。


#### Modbus数据类型

modbus协议基于以下基础数据类型：

Modbus基础数据类型


| 数据类型 | 对象类型 | 访问类型 | 描述 |
| --- | --- | --- | --- |
| 数字输入 | 1 bit | 只读 | 数字输入 |
| 线圈 | 1 bit | 读/写 | 数字输出 |
| 输入寄存器 | 16 bit (word) | 只读 | 模拟输入 |
| 保持寄存器 | 16 bit (word) | 读/写 | 模拟输出 |

对于每个基础数据类型，都定义了一个或多个功能码。这些功能码允许数字或模拟的输入和输出数据，以及内部变量被设置或直接从现场总线节点中读取。


#### Modbus 功能码描述

BL192Pro 现场总线节点支持的功能码如下表所示，要执行所需的功能，请指定各自的功能码和所选的输入或输出通道或寄存器的地址。

Modbus功能码列表


| 功能码 | 功能 | 访问类型 | 描述 |
| --- | --- | --- | --- |
| 0x02 | 读数字输入 | 只读 | 按1 bit 访问 |
| 0x01 | 读线圈 | 读/写 |  |
| 0x05 | 写单个线圈 | 读/写 |  |
| 0x0F | 写多个线圈 | 读/写 |  |
| 0x04 | 读输入寄存器 | 只读 | 按16 Bit访问 |
| 0x03 | 读多个寄存器 | 读/写 |  |
| 0x06 | 写单个寄存器 | 读/写 |  |
| 0x10 | 写多个寄存器 | 读/写 |  |

MODBUS 功能执行如下：

MODBUS TCP 主站（例如PC）使用特定功能码向BL192Pro现场总线节点发出请求；

BL192Pro现场总线节点接收数据报文，然后根据主站的请求，以正确的数据响应主站。

如果现场总线节点收到不正确的请求，它会向主站发送错误数据报文（异常）。

异常中包含的异常代码含义如下：

Modbus异常代码


| 异常代码 | 描述 |
| --- | --- |
| 0x01 | 非法功能 |
| 0x02 | 非法数据地址 |
| 0x03 | 非法数据值 |
| 0x04 | 从机设备故障 |

请求

### OPC UA通信示例

BL192Pro的OPC UA连接操作说明和BL191 OPC UA连接操作一样，所以这里通信示例直接引用BL191的OPC UA操作示例。


#### UaExpert与BL191通信示例

以BL191搭配Y01+Y31+Y41（4DIDO+4AI+4AO），自带RS485采集01、02、03、04功能码数据为例。RS485配置参考4.8.5.5Modbus设置。


#### OPC UA网页配置

![image](钡铼技术 EdgeIO控制器系列BL192Pro_说明书_V1.1-images/image133.png)

步骤：（1）点击“数据服务”选择“OPC UA设置”。（2）点击“启用”。（3）填写OPC UA服务端名称，可以自定义，方便OPC UA客户端搜索区分不同的OPC UA服务器。如：填写“EdgeIO”。（4）OPC UA 服务端的端口号，默认：4840。（5）安全策略选择。如选择“无”。（6）是否允许匿名，因使用签名方式，则允许匿名不打钩。（7）填写用户名和密码，客户端连接时需要填写这个用户名和密码。（8）选择数据，可以选择需要上传的数据，默认选择全部数据上传。（9）点击“保存并应用”。


#### 用UaExpert客户端连接收发数据

打开UaExpert（OPC UA客户端），输入OPC UA服务器IP和端口。

![image](钡铼技术 EdgeIO控制器系列BL192Pro_说明书_V1.1-images/image134.png)

点击搜索，点击搜索到的OPC UA服务器，输入设置的用户名和密码，点击OK。

![image](钡铼技术 EdgeIO控制器系列BL192Pro_说明书_V1.1-images/image135.png)

点击连接，连接成功后可以查看到数据节点。

![image](钡铼技术 EdgeIO控制器系列BL192Pro_说明书_V1.1-images/image136.png)

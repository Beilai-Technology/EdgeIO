## 产品简介

### 概述

Modbus协议边缘I/O控制器是钡铼技术推出的工业级EdgeIO控制器，作为一款集数据采集、逻辑控制、远程运维于一体的多功能边缘计算设备，BL190 支持 1-3 个 IO 扩展槽位，用户可根据现场需求自由组合数字量、模拟量、温度、串口等多种 I/O 模块，灵活适配各类工业自动化场景。例如，BL190可以搭配3块Y11（8DI）组成24DI独立式IO模块，或者混搭不同类型的IO板，如Y11（8DI）、Y31（4AI）、Y52（2PT）即可组合成8DI+4AI+2PT独立式IO组成一个既有数字输入（DI）、模拟输入（AI）、又有热电阻输入（PT）的IO模块。它不仅可以作为 PLC 的远程 IO 扩展，更能独立完成寄存器运算、逻辑判断等控制任务，有效降低系统成本和复杂度。

一台 BL190，即可替代传统“PLC + I/O 模块 + 网关”的繁琐组合。

![image](钡铼技术EdgeIO控制器系列BL190_说明书_V1.1-images/image3.jpeg)

BL190 Modbus协议边缘I/O控制器采用电气隔离技术，通过EMC/EMI测试及-45~80℃高低温验证，内置独立硬件看门狗，确保在严苛环境下长期稳定运行。广泛应用于智能制造、能源电力、智慧楼宇、轨道交通、现代农业等领域，为工业物联网和自动化系统提供高可靠、易部署、易维护的边缘层解决方案。


### 典型应用

典型应用案例：包装产线数据采集与 SCADA 集成

背景

某食品包装工厂拥有一条自动化灌装线，包含灌装机、封口机、贴标机、装箱机等 8 台设备。原有控制系统为独立的 PLC 和普通 I/O，现场数据（如产量计数、故障报警、设备运行状态）无法集中监控。工厂已部署 SCADA 系统（支持 Modbus TCP），但设备层数据接口不统一，需要人工巡视并记录产量，导致生产统计滞后，故障响应慢。

痛点总结：

设备分散，各机台独立运行，无统一数据平台。

普通 I/O 模块无法直接与 SCADA 通信。

需要增加 PLC 作为主站，但点位不多、改造成本偏高。

无法远程查看产量和故障，管理人员依赖现场报表。

改造方案

采用 BL190 作为每个机台的边缘节点，替代原有的普通 I/O 模块，并将数据统一上传至 SCADA 系统。

硬件配置（以灌装机为例）：

选用 Y11（8DI）：采集灌装机运行/待机/故障干接点、安全门状态、物料到位传感器

选用 Y22（8DO）：控制灌装机启停、报警灯、电磁阀

选用 Y31（4AI）：采集灌装压力（420mA）、液位传感器

Modbus RTU采集：采集灌装瓶数脉冲，本地累积产量

本地逻辑控制：

利用 BL190 内置 Web 配置实现配置

液位低于下限 → 打开进料阀（DO），同时上报 SCADA

安全门打开 → 立即停止灌装机（DO），并记录故障原因

每日产量脉冲自动累加，每日 00:00 自动清零，同时将前一天总产量写入保持寄存器供 SCADA 读取

Modbus TCP 对接 SCADA：

SCADA 系统通过以太网轮询各 BL190 的寄存器地址

数字量输入（DI）地址 2000~2007 → 设备状态

数字量输出（DO）地址 1000~1007 → 远程控制启停

模拟量输入（AI）地址 3000~3003 → 压力、液位

保持寄存器 40000~40009 → 当日产量、累计产量、故障代码

每个机台的 BL190 作为 Modbus TCP 服务器（默认端口 502）

双网口级联简化布线：

将 8 台 BL190 通过菊花链方式连接（ETH0 接上一台，ETH1 接下一台），仅需一根总线连接至车间交换机，节省布线成本。

远程运维：

设备工程师通过 BLRAT 远程工具，在办公室即可修改 BL190 的报警阈值（如液位上下限）、清零产量寄存器、检查 I/O 状态，无需进入生产车间。

案例点睛：BL190 以极低的成本将传统生产线上“各自为政”的普通 I/O 节点转变为标准的 Modbus TCP 设备，与 SCADA 无缝对接。其双网口菊花链布线、内置逻辑控制与远程运维功能，让中小型产线的数字化改造变得简单、经济、可复制。

### 功能特点

灵活的组合选项：用户可以根据需求自由组合1-3块Y系列IO板，支持多种配置，如24DI、16DI+8DO、8DI+4AI+2PT等，满足不同工业自动化场景的需求。

多样化的类型：支持数字量输入（DI）、数字量输出（DO）、模拟量输入（AI）、模拟量输出（AO）、热电阻输入（PT）和热电偶输入（TC）、数字量输入输出混合IO（DIDO）和脉冲输出/脉冲计数混合IO，适用于各种信号采集和控制任务。

工业级设计：通过EMC/EMI测试和-45~80℃宽温测试，能够在恶劣的环境条件下稳定运行，确保系统的可靠性。

标准化接口：通过标准Modbus TCP协议，与各类PLC和HMI无缝集成，简化了配置和使用过程。

边缘计算功能：内置逻辑控制和边缘计算，能够在本地执行一些简单的任务，减少对中央控制器的依赖。

交换机功能：配置2个RJ45接口，内置交换机功能，能够轻松建立线路拓扑结构，减少对额外交换机或集线器的需求，简化网络配置。

数据采集：自带1路隔离的RS485，支持Modbus RTU主站/从站双模式，可直连接智能仪表、传感器等设备，也可作为从站响应上位机指令；也可以通过网口采集Modbus TCP设备数据。

远程维护：集成BLRAT（Beilai Remote Access Tool），支持远程固件升级及参数配置，无需到现场调试与修改。

### EdgeIO控制器连接

BL190 EdgeIO控制器有2个以太网接口，内部集成交换机功能，工作在存储转发操作模式，每个端口支持10/100 Mbit的传输速度以及全双工和半双工传输模式。

EdgeIO控制器只能通过ETH 0接口连接到基于以太网的现场总线中，ETH1用于连接其他需要接入以太网的节点。

内部集成的交换机支持旁路模式，当EdgeIO控制器系统故障时可以自动启动旁路模式，自动维持 ETH 0 和 ETH 1的链接。

这些以太网接口的接线符合 100BaseTX 的规范，该规范规定使用 5 类双绞线电缆作为连接电缆。可以使用最大长为 100 m的电缆类型 S/UTP（屏蔽非屏蔽双绞线）和 STP（屏蔽双绞线）。

模拟输入模块的电信号数值（一般是传感器）和实际工程数值存在线性关系，它们的公式如下（以4-20mA为例）：

实际工程数值 =（电流值 - 4）*（（最大值 – 最小值）/（20 - 4））+最小值

以 4-20mA 类型的水位传感器测量水塔深度为例：

已知水位传感器量程是0-100m，电流数据5.6mA，计算水塔深度：

代入公式：

(5.6 - 4) * ((100 - 0) / (20 - 4)) + 0 = 10

水塔深度是10m。

#### 概述

Modbus 是一种独立于制造商的开放式现场总线标准协议，适用于制造和过程自动化中的各种应用。

MODBUS 是一种应用层消息传递协议，位于 OSI 模型的第 7 层，可以在不同类型的总线或网络上连接的设备之间进行客户端/服务器通信。

几种常用的网络如下：

TCP/IP over Ethernet。

多种媒体异步串行传输（有线：EIA/TIA-232-E、EIA-422、EIA/TIA-485-A；光纤、无线电等）。

MODBUS PLUS，高速令牌。

MODBUS 是一种请求/应答协议，提供由功能代码指定的服务。

MODBUS 协议允许在所有类型的网络架构内轻松通信。

![image](钡铼技术EdgeIO控制器系列BL190_说明书_V1.1-images/image82.png)

Modbus 网络架构

MODBUS 协议定义了一个独立于底层通信层的简单协议数据单元 (PDU)。 MODBUS 协议在特定总线或网络上的映射可以在应用数据单元（ADU）上引入一些附加字段。

![image](钡铼技术EdgeIO控制器系列BL190_说明书_V1.1-images/image83.png)

Modbus 数据帧

更多关于 Modbus 开放协议规范的细节可以在网站www.modbus.org查看。


#### Modbus TCP

Modbus TCP协议是Modbus协议的一种变体，该协议经过优化，可通过TCP/IP连接进行通信。该协议设计用于现场级的数据交换（即用于过程映像中的 I/O 数据交换）。在服务端，所有数据包都通过端口号为 502 的 TCP 连接发送。

一般 Modbus TCP 报文如下：

Modbus TCP 报文

#### Modbus数据编码

MODBUS对地址和数据项使用“大端”表示。这意味着当传输大于单个字节的数字量时，首先发送最高有效字节。


#### Modbus数据类型

modbus协议基于以下基础数据类型：

Modbus基础数据类型


| 数据类型 | 对象类型 | 访问类型 | 描述 |
| --- | --- | --- | --- |
| 数字输入 | 1 bit | 只读 | 数字输入 |
| 线圈 | 1 bit | 读/写 | 数字输出 |
| 输入寄存器 | 16 bit (word) | 只读 | 模拟输入 |
| 保持寄存器 | 16 bit (word) | 读/写 | 模拟输出 |

对于每个基础数据类型，都定义了一个或多个功能码。这些功能码允许数字或模拟的输入和输出数据，以及内部变量被设置或直接从现场总线节点中读取。

MODBUS 功能执行如下：

MODBUS TCP 主站（例如PC）使用特定功能码向 BL190 EdgeIO控制器节点发出请求；

BL190 EdgeIO控制器节点接收数据报文，然后根据主站的请求，以正确的数据响应主站。

如果现场总线节点收到不正确的请求，它会向主站发送错误数据报文（异常）。

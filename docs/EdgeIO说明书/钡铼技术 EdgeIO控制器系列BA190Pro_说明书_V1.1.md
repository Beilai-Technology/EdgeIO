## 产品简介

### 概述

智慧楼宇边缘I/O控制器是钡铼技术推出的工业级EdgeIO控制器，专为楼宇自动化和智能建筑系统设计。作为一款支持BACnet/IP、MQTT、Modbus TCP、OPC UA四大主流协议，集数据采集、跨协议转换、逻辑控制、远程运维于一体的多功能边缘计算设备，BA190Pro支持1-3个IO 扩展槽位，用户可根据现场需求自由组合数字量、模拟量、温度、串口等多种 I/O 模块。例如，BA190Pro可以搭配3块Y11（8DI）组成24DI独立式IO模块，或者混搭不同类型的IO板，如Y11（8DI）、Y31（4AI）、Y52（2PT）即可组合成8DI+4AI+2PT独立式IO组成一个既有数字输入（DI）、模拟输入（AI）、又有热电阻输入（PT）的IO模块。它无需多个网关即可同时对接楼宇自控系统、物联网云平台、PLC系统和企业管理平台，实现暖通空调、照明、安防、门禁、电梯、给排水等全楼宇设备的统一管控；同时可独立完成本地逻辑运算、联动控制和故障保护任务，有效降低系统集成成本和运维复杂度。

一台设备即可完成：

通过 Modbus RTU 采集现场仪表（电表、水表、热量表）数据。

通过 BACnet/IP 接入楼宇自控系统（BAS）。

通过 MQTT 将数据上传至云平台（阿里云、华为云等）。

通过 OPC UA 开放给上层管理软件（MES、ERP、能源管理平台）。

一台 BA190Pro，替代“专用 DDC + 多协议网关 + 云网关”的繁琐组合，实现从现场设备到 BAS、云平台、IT 系统的全面贯通。

![image](钡铼技术 EdgeIO控制器系列BA190Pro_说明书_V1.1-images/image3.jpeg)

BA190Pro 智慧楼宇边缘I/O控制器采用电气隔离技术，通过EMC/EMI测试及-45~80℃高低温验证，内置独立硬件看门狗，确保在严苛环境下长期稳定运行。广泛应用于商业综合体、写字楼、酒店、医院、学校、工业园区等各类智慧楼宇场景，为楼宇数字化转型与智能化升级提供高可靠、易部署、易扩展的边缘层解决方案。


### 典型应用

典型应用案例：商业综合体 HVAC 系统云边协同改造

背景

某大型商业综合体建筑面积 12 万㎡，拥有 30 台 AHU、50 台风机盘管、8 台冷水机组、15 块电力仪表和 6 块热量表。原有系统采用多套独立的 DDC 控制器，BAS 为霍尼韦尔系统，但存在以下问题：

现场仪表（电表、热量表）采用 Modbus RTU，无法直接接入 BACnet 网络，需要额外网关。

集团总部要求将能耗数据上传至阿里云 IoT 平台，原有系统不支持。

运维人员需要每周现场抄录数据、调整设定值，工作量巨大。

夏季用电高峰时无法远程优化空调策略，能耗居高不下。

改造方案

采用 BA190Pro 替换原有的 DDC 控制器和协议网关，单台 BA190Pro 覆盖一个设备层（如 4 台 AHU + 2 块电表 + 1 块热量表）。

Modbus RTU 采集：通过隔离 RS485 接口，周期读取电表的电压、电流、有功功率、电能，以及热量表的瞬时流量、累计热量。

I/O 本地控制：AI 采集回风温度、送风温度、CO₂浓度；AO 控制水阀开度（010V）和变频器频率；DO 控制风机启停、报警灯。

BACnet/IP 对接 BAS：将所有 I/O 点和 Modbus 采集的数据映射为 BACnet 对象（AI、AO、BI、BO），供霍尼韦尔 BAS 系统监控。

MQTT 上云：将能耗数据、关键运行参数（如 AHU 启停次数、累计运行时间）通过 MQTT 上传至阿里云 IoT 平台，集团运维中心大屏实时显示各楼层能耗排名、异常报警。

OPC UA 开放：将数据以 OPC UA 接口提供给第三方能源管理软件，进行深度数据分析与优化。

远程运维：工程师通过 BLRAT 工具远程修改温度设定值、PID 参数、时间表，甚至远程升级固件。

### 功能特点

灵活的组合选项：用户可以根据需求自由组合1-3块Y系列IO板，支持多种配置，如24DI、16DI+8DO、8DI+4AI+2PT等，满足不同楼宇自动化场景的需求。

多样化的类型：支持数字量输入（DI）、数字量输出（DO）、模拟量输入（AI）、模拟量输出（AO）、热电阻输入（PT）和热电偶输入（TC）、数字量输入输出混合IO（DIDO）和脉冲输出/脉冲计数混合IO，适用于各种信号采集和控制任务。

工业级设计：通过EMC/EMI测试和-45~80℃宽温测试，能够在恶劣的环境条件下稳定运行，确保系统的可靠性。

多协议：支持BACnet/IP、MQTT、Modbus TCP、OPC UA四大主流协议。

边缘计算功能：内置逻辑控制和边缘计算，能够在本地执行一些简单的任务，减少对中央控制器的依赖。

交换机功能：配置2个RJ45接口，内置交换机功能，能够轻松建立线路拓扑结构，减少对额外交换机或集线器的需求，简化网络配置。

数据采集：自带1路隔离的RS485，支持Modbus RTU主站/从站双模式，可直连接智能仪表、传感器等设备，也可作为从站响应上位机指令；也可以通过网口采集Modbus TCP设备数据。

远程维护：集成BLRAT（Beilai Remote Access Tool），支持远程固件升级及参数配置，无需到现场调试与修改。

## BA190Pro智慧楼宇边缘I/O控制器

### BA190Pro 智慧楼宇边缘I/O控制器概述

BA190Pro是BA190 BACnet/IP 协议边缘I/O控制器的增强版。

BA190Pro EdgeIO控制器包含BACnet/IP、MQTT、Modbus TCP、OPC UA四大主流协议。

BA190只支持 BACnet/IP 协议，可作为服务端向外部系统（如 HVAC、BMS、西门子 Desigo CC 等）提供标准化数据访问。

BA190的本机数据和从机数据的DI、DO、AI、AO分别对应BACnet/IP的BI、BO、AI、AO，详情请查看Modbus 寄存器映射。所有 BACnet 对象按创建顺序自动分配实例号（从 0 开始连续递增）。如BA190-Y31，生成 4 个 Analog Input 实例Analog Input.0至Analog Input.3。在对象属性中可查看关联的 Modbus 寄存器地址。

### EdgeIO控制器连接

BA190Pro有2个以太网接口，内部集成交换机功能，工作在存储转发操作模式，每个端口支持10/100 Mbit的传输速度以及全双工和半双工传输模式。

该EdgeIO控制器只能通过ETH 0接口连接到基于以太网的现场总线中，ETH1用于连接其他需要接入以太网的节点。

内部集成的交换机支持旁路模式，当EdgeIO控制器系统故障时可以自动启动旁路模式，自动维持 ETH 0 和 ETH 1的链接。

这些以太网接口的接线符合 100BaseTX 的规范，该规范规定使用 5 类双绞线电缆作为连接电缆。可以使用最大长为 100 m的电缆类型 S/UTP（屏蔽非屏蔽双绞线）和 STP（屏蔽双绞线）。

模拟量输入模块的电信号数值（一般是传感器）和实际工程数值存在线性关系，它们的公式如下（以4-20mA为例）：

实际工程数值 =（电流值 - 4）*（（最大值 – 最小值）/（20 - 4））+最小值

以 4-20mA 类型的水位传感器测量水塔深度为例：

已知水位传感器量程是0-100m，电流数据5.6mA，计算水塔深度：

代入公式：

(5.6 - 4) * ((100 - 0) / (20 - 4)) + 0 = 10

水塔深度是10m。

#### 概述

Modbus 是一种独立于制造商的开放式现场总线标准协议，适用于制造和过程自动化中的各种应用。

更多关于 Modbus 开放协议规范的细节可以在网站www.modbus.org查看。


#### Modbus TCP

Modbus TCP协议是Modbus协议的一种变体，该协议经过优化，可通过TCP/IP连接进行通信。该协议设计用于现场级的数据交换（即用于过程映像中的 I/O 数据交换）。在服务端，所有数据包都通过端口号为 502 的 TCP 连接发送。

一般 Modbus TCP 报文如下：

Modbus TCP 报文


| 字节 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 - n |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 定义 | 事务标识符 | 协议标识符 (始终为00) | 字段长度 | 从机地址 | Modbus 功能码 | 数据 |  |  |  |

#### 连接华为云配置

![image](钡铼技术 EdgeIO控制器系列BA190Pro_说明书_V1.1-images/image144.png)

操作说明：1、点击“云平台”-“华为云”，进入华为云配置界面。2、点击“启用”，认证方式选择“设备秘钥”。3、设备ID与华为云平台设备ID一致，密钥是华为云平台创建设备输入的密码。4、服务ID与华为云平台创建产品时的服务ID一致。5、地域：选择华北-北京四，选择其他可以填写IP地址。6、发布周期：60s。7、数据打包50个每包，自定义。8、点击“保存并应用”，把华为云配置下发到BL192，连接状态可以查询是否连接成功。

#### 连接thingsboard配置

Thingsboard云连接的是专业版云服务，域名为：thingsboard.cloud，即是北美地区thingsboard域名。连接其他thingsboard格式的云平台选择“其他thingsboard服务器”。

![image](钡铼技术 EdgeIO控制器系列BA190Pro_说明书_V1.1-images/image150.png)

操作说明：1、点击“云平台”-“Thingsboard”，进入thingsboard云配置界面。2、点击“启用”，ThingsBoard平台选择“其他ThingBboard服务器”。3、填写服务器IP或域名和端口。4、MQTT客户端ID、用户名、密码填写与thingsboard平台创建设备时选择MQTT Basic填写的内容一致。5、发布周期：60s。6、数据打包20个每包，自定义。7、点击“保存并应用”把thingsboard云配置下发到BL192，连接状态可以查询是否连接成功。

#### 设备发布数据格式

如果在配置时勾选了数据打包将会在一条消息中发送多个I/O数据点（数据点很多时会分开发送多条消息，每条消息包含多个数据点），不勾选时一条消息只对应一个I/O数据点，两种发布格式有少许区别，需要注意。

设备发布消息中有效载荷数据格式（数据打包）

MQTT发布数据格式


| 发布主题：对应配置的发布主题设置项 |
| --- |
| { "REG1000": 1, //本机DO读写标识和值 "REG2000": 1, //本机DI读写标识和值 "REG3000": 2, //本机AI读写标识和值 "REG4000": 3, //本机AO读写标识和值 "REG10000": 1, //串口采集从机01功能码读写标识和值 "REG20000": 1, //串口采集从机02功能码读写标识和值 "REG30000": 8, //串口采集从机04功能码读写标识和值 "REG40000": 10, //串口采集从机03功能码读写标识和值 "ipv4-address": "192.168.3.2", //本机IP地址 "time": "1698910380", //时间标识，数据发布时间戳UTC格式 "seq": 1 //数据包数，第几包 "retransmit":"enable"//重传标识，表示历史数据（重传历史数据才有此标识，实时数据无此标识） } |

注：

本机I/O数据点读写标识：

MQTT本机I/O标识符


| 数据名称 | 读写标识 | 数据类型 | 说明 |
| --- | --- | --- | --- |
| 开关量输出DO | REG1000~1999 | Switcher | 0为断开，1为闭合 |
| 开关量输入DI | REG2000~2999 | Switcher | 0为断开，1为闭合 |
| 模拟量输入AI | REG3000~3999 | Value | 真实值=原值 |
| 模拟量输出AO | REG4000~4999 | Value | 真实值=原值 |

串口模块从机I/O数据点读写标识：

MQTT从机数据点标识符


| 数据名称 | 读写标识 | 数据类型 | 说明 |
| --- | --- | --- | --- |
| 线圈状态 | REG10000~19999 | Switcher | 根据从机数据定义 |
| 输入线圈 | REG20000~29999 | Switcher | 根据从机数据定义 |
| 保持寄存器 | REG40000~49999 | Value | 根据从机数据定义 |
| 输入寄存器 | REG30000~39999 | Value | 根据从机数据定义 |
